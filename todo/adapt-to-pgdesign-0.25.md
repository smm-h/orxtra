# Adapt to pgdesign 0.25.0 (breaking release)

pgdesign 0.25.0 is a large breaking release (content-addressed schema
identity, a chain-based migration system, branded codegen, a document-shape
gate). This todo lists orxtra's verified adaptation surface. See pgdesign's
CHANGELOG 0.25.0 for the full breaking list.

## Required adaptations

1. **Stamp schema TOMLs.** Every schema document now requires a top-level
   `format_version = 1`; documents without it are rejected, and unknown keys
   are now hard errors (previously warnings). pgdesign ships
   `scripts/stamp_format_version.sh` as the one-liner remediation.
2. **Regenerate `schema/_generated/`** with the new binary and commit.
   Expect large diffs dominated by canonical reordering (~1000 changed lines
   in schema_executor.py, ~600 in tables_trace.py) plus the new header
   wording (`Code generated by pgdesign. DO NOT EDIT.`) and a revision
   stamp line. This is a full regenerate-and-review, not a header change.
   Verify with:
   ```
   pgdesign codegen --lang python --mode ddl --split-mode faceted --check \
     --output schema/_generated schema/pgdesign.toml
   ```
   (`scripts/check_schema_codegen.sh` needs NO changes — its output parsing
   was verified compatible. Its `__init__.py` orphan-handling branch is now
   dead code and may optionally be removed.)
3. **Migration system changes** (verified against this repo's tests and
   wrapper):
   - `migrate generate --version` is REMOVED (migrations are content-derived
     chain edges, not semver files); `--config` is now `--project-config`.
     `tests/test_db_migration.py:1761-1775` hard-codes both and the
     `0.1.0.toml` filename assertion — rewrite the test around chain-mode
     generate (assert `migrations/chain/edge-*.json`).
   - Any database with an existing `pgdesign_migrations` tracking table
     requires a one-time `pgdesign migrate upgrade` before ANY other migrate
     subcommand (they hard-error pointing at it until then).
   - The CLI wrapper (`cli/src/orxtra/cli/_db.py`) has no upgrade path — add
     a `db migrate upgrade` subcommand wrapping
     `pgdesign migrate upgrade <schema_dir> --db ... --dir ...`.
   - `migrate plan` is now a pure chain preview (no DB); per-database
     pending state is `migrate status`'s job.

## Effort

Medium: the regeneration itself is mechanical; the test rewrite and wrapper
subcommand are small, deliberate changes.
